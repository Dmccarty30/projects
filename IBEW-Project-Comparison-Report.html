actionable

⚡ Journeyman-Jobs — To Complete

  • Build a backend scraping pipeline — the app has no server. Port Trampbook's scraper adapters or build a Firebase Functions-based equivalent. Without this, the app has no job data.
  • Complete the settings screen — TODO-TASKS.md outlines the full scope. Wire every setting to Firestore.
  • Finish circuit background redesign — 10-phase plan exists (implementation-plan.md). Execute Version A + B, then pick a winner.
  • Replace 92 print() calls — use the existing StructuredLogger. This is a quick win for production readiness.
  • Migrate lib/legacy/ shims — 144 nodes of FlutterFlow compatibility code. Remove or absorb into core.
  • Write a real TODO.md — the file is empty. Consolidate the scattered planning docs into one roadmap.
  • Add a data layer — 116 nodes in data/ package. Needs real repositories and data sources beyond Firestore SDK.
  • Estimated effort: 4-6 weeks for a solo dev to reach feature parity with Trampbook.

🌐 Trampbook — To Complete

  • Fix 32 test failures — tests mock old Supabase REST API. Update mocks to use Drizzle ORM. Quick win.
  • Split routers.ts — 1377 lines in one file. Break into auth, jobs, locals, notifications, admin routers.
  • Refactor registerAuthRoutes — cyclomatic complexity 64. Split into handler functions per route.
  • Refactor parseUnionActiveTable — cognitive complexity 165, 8 loops. Extract parser strategies.
  • Complete hybrid scraper bake-off — plan.md phases P3-P5: run hybrid vs baseline, merge winners datasets, wire feature flags.
  • Open firewall for HTTPS — deploy config is ready, just needs the port opened.
  • Implement "Hey SLIM" wake word — Web Speech API continuous listening.
  • Add pull-to-refresh — mobile gesture for Job Calls page.
  • Estimated effort: 2-3 weeks to reach production-ready state.

💡 Strategic Recommendation

If you can only finish one: Trampbook is closer to production, has a real data pipeline, and is already deployable. The 2-3 week effort to clean up tests and refactor is lower risk than Journeyman-Jobs' 4-6 weeks to build a backend from scratch.

If you want the best long-term product: Consider converging — use Trampbook's backend (tRPC, Drizzle, scrapers, RAG) as the API and Journeyman-Jobs' Flutter app as the mobile frontend. Journeyman-Jobs' cleaner code and native mobile UX would sit on top of Trampbook's proven data layer. This eliminates JJ's biggest gap (no backend) and gives TB a native mobile client.

If they must stay separate: Trampbook is the ship-now winner. Journeyman-Jobs is the better-engineered codebase that needs a backend to be useful.
