🔴 CRITICAL: Do Not Run Both Projects in Parallel

Running two separate scrapers against the same IBEW local union websites risks IP bans, duplicate data, and wasted proxy costs. Pick ONE project as the production system and migrate the other's assets into it. This report assumes you will decide which project goes to production based on the migration outcome — but the critical path items below must be done regardless of which one you choose.

✅ The Two Projects Are Complementary

Journeyman-Jobs has the better mobile app (Flutter, native, offline, design system) and the better ML pipeline (spaCy NER, SVM URL classifier). Trampbook has the better backend (tRPC, Drizzle, MySQL, 10 migrations), better scraper architecture (adapter pattern, 244+ locals, eval framework), and better AI/RAG system. The migration plan below moves each strength to the project that needs it.

tRPC API Gateway + Express Server

CRITICAL
Journeyman-Jobs has no backend server — it depends entirely on Firebase SDK calls from the Flutter client. This is the single biggest blocker to production. Trampbook has a full Express + tRPC server with 43 typed routes, end-to-end type safety, and JWT auth.

What to migrate:
  • 1Copy server/_core/index.ts (Express bootstrap) and server/_core/ directory to a new server/ directory in Journeyman-Jobs
  • 2Copy server/context.ts (tRPC context with auth middleware)
  • 3Copy server/routers.ts — but split it first (it's 1377 lines). Break into: auth.router.ts, jobs.router.ts, locals.router.ts, notifications.router.ts, admin.router.ts
  • 4Replace Firebase Auth calls in Flutter with tRPC API calls (keep Firebase Auth as the auth provider, but route data through tRPC)
  • 5Generate tRPC client types and use in Flutter via tRPC Dart package or a generated REST layer
Source (Trampbook)
server/_core/index.ts · server/context.ts · server/routers.ts

  • 5Run drizzle-kit migrate against a fresh MySQL instance

Risk Assessment & Mitigation

critical analysis

🔴 High Risks

Credential Exposure (v3)

BrightData, Firebase, and OpenAI credentials are in git history. Even after rotation, if the repo is public or shared, historical commits expose them. Mitigation: Rotate all credentials, use BFG repo-cleaner to scrub history, move all secrets to .env immediately.

parseUnionActiveTable (TB)

Cognitive complexity 165 with 8 nested loops. This function is a bug factory — any change to UnionActive's HTML will break it in unpredictable ways. Mitigation: Split into row parsing, detail parsing, and normalization. Add unit tests with frozen HTML snapshots.

Firestore → MySQL Data Loss

If migrating JJ to MySQL, Firestore's schemaless nature means some documents may have fields that don't fit the Drizzle schema. Mitigation: Write a validation script that checks every Firestore document against the Drizzle schema before migration. Log and manually resolve mismatches.

🟡 Medium Risks

ML Model Drift

v3's spaCy NER model was trained on a specific dataset. If IBEW websites change their HTML structure, the model's accuracy will degrade. Mitigation: Run the eval framework weekly. Set an accuracy threshold (e.g., 85%). If it drops, retrain with new labeled data.

Scraper IP Bans

Trampbook's direct fetch (no proxy) may get IP-banned by IBEW websites that detect scraping. v3's BrightData proxy avoids this but is expensive. Mitigation: Start without proxy. If bans occur, add BrightData proxy for problematic locals only. Store credentials in .env.

Flutter → tRPC Migration

Replacing Firestore SDK calls with tRPC API calls in Flutter is a large refactor (14 feature directories). Risk of introducing bugs in working features. Mitigation: Migrate feature-by-feature. Keep Firestore as fallback until each feature is verified. Use the existing test suite to catch regressions.
